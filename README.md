# AI Site Search Chatbot

※ 100% AI 生成のため自己責任でご利用ください。

WordPress サイト訪問者向けに、サイト内検索と生成 AI を組み合わせたチャットボットを提供するプラグインです。

## 動作要件

- PHP 8.1 以上
- WordPress 7.0 以上（Connectors API / AI Client がコアに必要）
- 利用したい AI プロバイダーの公式プロバイダープラグイン（AI Provider for OpenAI / AI Provider for Anthropic / AI Provider for Google のいずれか）を導入し、`設定 > コネクタ` で API キーを接続していること

Composer 依存はありません。プラグイン本体は WordPress コアの AI Client（`wp_ai_client_prompt()`）を通じて接続済みプロバイダーにリクエストを送るだけです。

## 現在実装済み

- 公開 REST API: POST /wp-json/ai-site-search-chatbot/v1/chat
- サイト内検索: 公開投稿タイプを対象にキーワード検索。指定したカスタムフィールドと、ショートコード・プラグインの動的ブロックが出力する文章も検索可能
- 続けての質問: 直前の会話を引き継ぎ、「8月のものは？」のような入力で前の質問を絞り込み
- 再検索の提案: 該当するページがない場合、サイト内で実際に結果が出るキーワードだけを提案
- AI 応答: WordPress 7.0 の Connectors API 経由で接続した OpenAI、Claude (Anthropic)、Google Gemini を切り替えて利用可能
- 汎用サイト案内: サイト名、説明文、公開コンテンツ要約をもとに、サイトの使い方や掲載情報の種類などの案内質問にも AI が応答
- 管理画面: プロバイダーの接続状況表示、モデル名、システムプロンプト、参照件数、表示場所、デザインの設定
- Saved Knowledge Base: 一般化した質問・回答ペアを管理画面でレビューし、承認状態を切り替えながら再利用可能
- ナレッジ管理: Saved Knowledge Base を CSV でエクスポート / インポート可能
- 接続確認: モデル ID のバリデーション、および管理画面上でのチャットテスト
- 利用状況確認: 最新 50 件の公開チャット履歴を管理画面で確認可能。管理画面に表示される使用トークン数は目安であり、実際のプロバイダー側使用量や課金と差異が出る場合があります。
- チャットログの再取得: 設定不備・プロバイダーエラー・検索結果なし・利用上限到達などで AI 以外の代替応答になったログに「再取得」ボタンを表示。成功時は Saved Knowledge Base の下書きを自動生成し、再取得後も失敗した場合は質問を無駄にしないよう回答欄が空の下書きを自動作成
- 参照元投稿の確認: ナレッジ編集画面で参照元投稿のタイトル表示・本文プレビュー・別タブでの表示/編集
- 参照元の公開状態の追従: 公開されなくなった参照元を持つナレッジを再利用から除外し、必要に応じて再検索・再生成して下書きに戻す
- 古い情報の除外: 同じお知らせの古い版を検索結果から除外し、最新の情報で回答。日付に依存するナレッジ下書きには要確認の目印を表示
- フロント UI: 自動表示、ショートコード、Gutenberg ブロックに対応した訪問者向けチャット画面
- デザイン切り替え: Business / Cute の 2 テーマを選択可能

## インストール

1. WordPress 7.0 以上で、利用したい AI プロバイダーの公式プロバイダープラグイン（AI Provider for OpenAI / AI Provider for Anthropic / AI Provider for Google）を導入・有効化
2. 管理画面 設定 > コネクタ で対象プロバイダーの API キーを入力して接続
3. 本プラグインを有効化し、管理画面 設定 > AI Site Search Chatbot を開く
4. 接続済みのプロバイダーを選び、モデル ID を設定
5. 必要に応じて「Validate Connection and Model」と「Run Admin Chat Test」で接続確認
6. 「Enable chatbot display on the public site」を有効化して保存

補足: API キーはこのプラグインではなく WordPress コアの `設定 > コネクタ` 画面で一元管理されます（複数の対応プラグインで共有可能）。必要に応じて、wp-config.php またはサーバー環境変数（例: `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GOOGLE_API_KEY`）を定義すると、コネクタ画面の保存値よりそちらが優先されます。

### Claude (Anthropic) を使う場合

AI Provider for Anthropic プラグインを有効化し、[Anthropic コンソール](https://platform.claude.com/settings/keys) で発行した API キーを `設定 > コネクタ` に登録してください。本プラグインの設定画面でモデル ID に `claude-sonnet-4-6` または `claude-opus-4-7` などを指定します。

## 使い方

表示方法は 3 通りあります。

### 1. 全ページまたはトップページに自動表示

管理画面の Display Location で以下を選ぶと、ショートコードを置かなくても自動表示されます。

- Display on all pages
- Display only on the site top page

### 2. ショートコードで表示

Display Location を Display only where the shortcode is placed に設定したうえで、固定ページや投稿本文に次を配置します。

```text
[ai_site_search_chatbot]
```

任意属性:

```text
[ai_site_search_chatbot title="サイト案内チャット" greeting="ご質問をどうぞ。サイト内を検索して回答します。"]
```

テーマも個別指定できます。

```text
[ai_site_search_chatbot theme="cute"]
```

### 3. Gutenberg ブロックで表示

ブロックエディタで AI Site Search Chatbot ブロックを追加すると、ショートコードを手入力せずに配置できます。

## 主な設定項目

- AI Provider: OpenAI / Claude (Anthropic) / Google Gemini（各プロバイダーの接続は 設定 > コネクタ で管理）
- Model: 利用するモデル ID をそのまま指定
- System Prompt: 回答方針を調整するシステムプロンプト。変更しなければデフォルトに従い、プラグイン更新で自動的に改善される。カスタマイズした場合は保持され、デフォルトが新しくなると切り替えるかどうかを選べるお知らせを表示
- Maximum Sources: 回答時に参照する検索結果の上限件数
- Custom Fields to Search: 検索して AI に渡すカスタムフィールドのキー（1 行に 1 つ、末尾 `*` で前方一致）。初期状態は空。値は回答を通じて訪問者に見える可能性があるため、公開してよい情報のフィールドだけを指定
- Conversation History: 続けての質問で AI に送る直前のメッセージ数（初期値 4、範囲 2〜10）。1 件ごとに続けての質問 1 回あたり最大約 650 入力トークン増える
- Shortcode and Block Output: ショートコードとプラグインの動的ブロックが出力する文章を検索するか（初期値オン）。重いショートコードを多用して回答が遅くなる場合はオフに
- AI Reply Limit (10 minutes / 1 hour): 同一接続からの AI 応答回数の上限。まずは 10 分で 6 から 10 回、1 時間で 20 から 40 回程度を目安に調整
- Saved Knowledge Base: 一般化した質問・回答ペアの確認、承認状態の切り替え、CSV のエクスポート / インポート
- Display Location: 全ページ表示、トップページのみ表示、ショートコードまたはブロック設置箇所のみ表示
- Chatbot Design: Business / Cute
- Uninstall Data Policy: プラグイン削除時に設定・ログ・保存済みナレッジを保持するか削除するかを選択
- Recent Visitor Chat Logs: 公開チャットの質問、回答、時刻、参照件数、マスク済み IP を管理画面で確認

## 補足

- 公開エンドポイントのため、簡易レート制限を実装しています。
- 返答には参照元 URL 一覧を同時に返します。
- サイト内検索結果が少ない場合でも、サイト名、説明文、公開コンテンツ要約を使ったサイト案内向け回答を返せます。
- 管理画面に表示される使用トークン数は目安であり、実際のプロバイダー側使用量や課金と差異が出る場合があります。

## 変更履歴

### 1.3.0

- 続けての質問で前の会話を引き継ぐようにした。ウィジェットが直近のメッセージを質問と一緒に送り、既存のルート判定の AI 呼び出しで前の質問の続きかどうかを判断して、単体で意味が通じる質問（`standalone_question`）に書き直す。書き直した質問を検索・回答キャッシュ・保存済みナレッジ・ログに使い、回答生成にも会話を渡す。ログには訪問者の実際の入力を「続けて入力された内容」として表示。追加の AI 呼び出しなし
- 引き継ぐメッセージ数の設定「会話履歴」を追加（初期値 4、範囲 2〜10）。会話履歴はブラウザから送られるため、サーバー側でも件数と長さ（1 件 500 文字）を制限
- 再検索キーワードの提案を、サイト内で実際に結果が出る語だけに限定。投稿タイトル（「―」などで区切られたシリーズ名を含む）とタクソノミーのタームから候補を作り、実際に検索して結果が出るものだけを残す（1 時間キャッシュ、投稿・ターム更新時に破棄）。カスタム投稿タイプ名を添えて AI に渡し、リストに含まれる語だけを提案させる。AI を使わない「見つかりませんでした」の回答にも数語を表示。回答キャッシュのバージョンを更新
- 「検索対象のカスタムフィールド」設定を追加。指定したキーの値を検索（通常検索と部分一致の予備検索の両方）し、シリアライズや JSON の値も平文にして本文・抜粋・AI への入力に含める。URL と WordPress 内部用のキーは除外。パスワード保護された投稿は対象外
- ショートコードとプラグインの動的ブロックが出力する文章でも検索できるようにした（設定「ショートコードとブロックの出力」、初期値オン）。展開した文章を投稿メタ `_aiscb_shortcode_text` にキャッシュし、投稿の更新時または 12 時間で作り直す。1 回の検索で展開するのは最大 10 件、対象は新しい順に 100 件まで。アンインストール時にキャッシュも削除
- 検索結果の本文で、ショートコードより先に動的ブロックを展開するようにした（展開中はグローバルな投稿を対象の投稿に切り替える）
- デフォルトのシステムプロンプトが更新に追従するようにした。デフォルトのときは空で保存し、実行時にその時点のデフォルトを使う。過去のデフォルトを翻訳と英語原文の両方で判別し、そのまま保存されているサイトは更新後に自動で現在のデフォルトへ移行。カスタマイズしたプロンプトは変更せず、デフォルトが新しくなると「新しいデフォルトに切り替える」「今のプロンプトを使い続ける」を選べるお知らせを表示。今後デフォルトを変更する際は `SYSTEM_PROMPT_DEFAULT_VERSION` を更新し、旧デフォルトを `get_legacy_default_system_prompts()` に移す
- 不具合修正: 部分一致の予備検索で、`$wpdb->prepare()` に渡す値の順番がプレースホルダーの順番と食い違っていたため、一度も結果を返していなかった
- 検索語から日本語のかぎ括弧（「」『』）を取り除くようにした
- 翻訳ファイル（`.pot` / `ja.po` / `.mo`）を更新

### 1.2.0

- Saved Knowledge Base の編集画面で、参照元投稿 ID ごとにタイトルを表示（マウスオーバー）し、クリックで本文をポップアップ表示、別タブでの表示・編集ができるようにした（`GET /wp-json/ai-site-search-chatbot/v1/knowledge-base/source-posts`）。非公開・パスワード保護・削除済み・閲覧権限のない投稿は色分けして表示
- 承認済みナレッジの再利用判定で、公開されなくなった参照元投稿を除外。参照元がすべてなくなったナレッジは即座に使われなくなり、投稿の状態変更を契機に WP-Cron でサイト内検索をやり直し、回答と参照元を再生成して下書きに戻す（回答が得られない場合も理由を確信度メモに記録して下書きに戻す）。1 日 1 回の巡回処理でも検出
- サイト内検索の結果から古い情報を除外。日付と数字を除いたタイトルと本文冒頭がほぼ同じ新しい投稿がある場合は最新のものだけを残す（内容の異なる連載記事や定期報告は両方残す）。AI には公開日と今日の日付を渡し、最新の情報を優先させる。追加の AI 呼び出しなし
- 参照元投稿が現在の検索結果の新しい投稿に置き換えられている承認済みナレッジは再利用しない
- 日付や一時的・期限付きの情報を含むナレッジ下書きは破棄せず保存し、「日付を確認」の目印（マッチングヒント `date_review`）と確信度メモで承認前の確認を促す。判定はナレッジ生成時の AI 応答に含まれる `time_sensitive` 項目と、具体的な日付表記のローカル検出で行う

### 1.1.0

- 設定不備・プロバイダーエラー・検索結果なし・利用上限到達などで AI 以外の代替応答になったチャットログに「再取得」ボタンを追加。訪問者の質問をもう一度ルート判定・サイト内検索・AI 回答生成にかけ直せるようにした
- 再取得が成功した場合、既存の自動下書き生成フローを利用して新しい回答を Saved Knowledge Base の下書きとして保存（「ナレッジベースの自動下書き」が有効な場合）
- 再取得しても AI 回答が得られなかった場合は、質問文だけを保持した回答欄が空の下書きエントリを自動作成し、2 回失敗した質問もログに埋もれず手動回答の対象として残るようにした
- 不具合修正: `build_rule_based_search_queries()` 内の `trim( $trimmed_question, "...多バイト文字を含むマスク..." )` が、`trim()` の文字マスク引数をバイト単位で処理してしまうことに起因し、日本語などマルチバイト文字で始まる質問の先頭文字が破損することがあった。Unicode 対応の正規表現による trim に置き換えて修正（サイト内検索のキーワード抽出精度、および再取得時にナレッジ下書きへ保存される質問文の正確性に影響していた）

### 0.7.0
