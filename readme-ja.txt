サイト内検索と生成 AI を組み合わせ、訪問者向けに応答するチャットボットを追加します。

== 説明 ==

AI Site Search Chatbot は、サイト訪問者向けのチャットウィジェットを追加するプラグインです。訪問者が質問すると、プラグインは公開コンテンツ（投稿、固定ページ、その他の公開投稿タイプ）を検索し、その検索結果と質問を、WordPress コアの Connectors API 経由で接続された AI プロバイダーに送信します。AI はサイト自身のコンテンツをもとに回答し、参照元のリンクも合わせて提示します。

本プラグイン自体は AI 連携や API キーの保存機能を持ちません。WordPress 7.0 で導入された AI Client（`wp_ai_client_prompt()`）を利用し、以下いずれかの公式プロバイダープラグインが提供する接続を使用します。

* AI Provider for OpenAI
* AI Provider for Anthropic (Claude)
* AI Provider for Google (Gemini)

`設定 > コネクタ` でいずれかのプロバイダープラグインを導入・接続したうえで、本プラグインの設定画面でその接続を選択してください。

= 主な機能 =

* チャットウィジェットを動かす公開 REST エンドポイント（`POST /wp-json/ai-site-search-chatbot/v1/chat`）
* 公開投稿タイプを対象にしたサイト内検索と、検索結果に基づく AI 回答
* 続けての質問で前の会話を引き継ぎ、「8月のものは？」のような入力で前の質問を絞り込み可能（引き継ぐメッセージ数は設定可能）
* 指定したカスタムフィールド、およびショートコードやプラグインの動的ブロックが出力する文章の検索
* 該当するページがない場合の再検索の提案は、サイト内で実際に結果が出るキーワードだけに限定
* 直接一致するコンテンツがない場合でも、サイト名・説明文・公開コンテンツ要約を使った汎用的なサイト案内回答
* サイトごとに AI プロバイダーとモデルを選択可能。接続確認と管理画面上でのチャットテストに対応
* Saved Knowledge Base: 一般化した質問・回答ペアをレビューし承認状態を管理することで、以降の類似質問に AI 呼び出しなしで応答可能。CSV エクスポート / インポートにも対応
* 設定不備・プロバイダーエラー・検索結果なし・利用上限到達などで AI 以外の代替応答になったチャットログに「再取得」ボタンを表示。再取得が成功した場合は Saved Knowledge Base の下書きを自動生成し、再取得しても失敗する場合は質問を無駄にしないよう回答欄が空の下書きを自動作成
* Saved Knowledge Base 編集画面での参照元投稿のプレビュー、公開されなくなった参照元を持つナレッジの自動処理、日付に依存する下書きへの要確認表示
* 同じお知らせの古い版を検索結果から除外し、最新の情報で回答
* 管理者以外のユーザーに Saved Knowledge Base の管理のみを許可する任意の権限（capability）
* 全ページ自動表示、トップページのみ自動表示、ショートコードまたは Gutenberg ブロックによる手動配置の 3 種類の表示方法
* Business / Cute の 2 種類のウィジェットデザイン
* 管理画面での訪問者チャットログ（直近 50 件）と日次 AI 利用状況の確認
* 公開チャットエンドポイントのレート制限（サイト全体の日次上限を含む）
* プラグイン削除時に設定・ログ・保存済みナレッジを保持するか削除するかを選べるデータ保持設定

= 外部サービスについて =

本プラグインが直接サードパーティサービスを呼び出すことはありません。チャットのリクエストは WordPress コアの AI Client に送られ、そこから `設定 > コネクタ` で接続した AI プロバイダー（OpenAI、Anthropic、Google のいずれか）へ、各公式プロバイダープラグイン自身の接続と API キーを使って送信されます。本プラグインが API キーを保存・送信することはありません。

データが送信されるのは、訪問者がチャットウィジェットで質問を送信したとき、または管理者が接続確認・管理画面チャットテスト・チャットログの再取得を実行したとき、および参照元の投稿が公開されなくなった保存済みナレッジをバックグラウンド処理（WP-Cron）で作り直すときだけです。1 回のリクエストには次の内容が含まれることがあります。

* 訪問者の質問。続けての質問の場合は、同じ会話の直前のメッセージ（「会話履歴」で設定した件数まで、初期値 4 件）。会話は訪問者のブラウザのタブ（sessionStorage）に最大 3 時間保持され、タブやブラウザを閉じると削除されます。
* 一致した公開投稿のタイトル、抜粋、本文の一部。ショートコードやブロックが出力する文章と、管理者が「検索対象のカスタムフィールド」で指定したカスタムフィールドの値を含みます。
* サイトに関する一般的な質問に答えるための、サイト名、キャッチフレーズ、いくつかの公開投稿のタイトル。
* 保存済みナレッジベースのための、質問、生成された回答、一致した検索結果（再利用できるエントリの作成と選択に使用）。

訪問者の IP アドレス、Cookie、アカウント情報はプロバイダーに送信しません。プロバイダーに送信された後の訪問者の質問がどのように扱われるかについては、各プロバイダーの利用規約・プライバシーポリシーをご確認ください。

* OpenAI: [https://openai.com/policies/](https://openai.com/policies/)
* Anthropic: [https://www.anthropic.com/legal](https://www.anthropic.com/legal)
* Google: [https://policies.google.com/](https://policies.google.com/)

== インストール ==

1. WordPress 7.0 以上で動作していることを確認してください。
2. 利用したい AI プロバイダーの公式プロバイダープラグイン（AI Provider for OpenAI / AI Provider for Anthropic / AI Provider for Google のいずれか）を導入・有効化します。
3. `設定 > コネクタ` を開き、対象プロバイダーの API キーを入力して接続します。
4. 本プラグインを導入・有効化します。
5. `設定 > AI Site Search Chatbot` を開き、接続済みのプロバイダーを選択してモデル ID を設定します。
6. 必要に応じて「Validate Connection and Model」と「Run Admin Chat Test」で動作を確認します。
7. 「Enable chatbot display on the public site」を有効化して保存します。
8. 表示方法を選びます。全ページ自動表示、トップページのみ自動表示、または `[ai_site_search_chatbot]` ショートコードや AI Site Search Chatbot ブロックによる手動配置のいずれかです。

== よくある質問 ==

= このプラグインは API キーを保存しますか？ =

保存しません。API キーは WordPress コアの `設定 > コネクタ` 画面で、OpenAI / Anthropic / Google の各公式プロバイダープラグインにより一元管理されます。本プラグインはその接続を利用してリクエストを送信するだけです。

= サイト内検索で良い候補が見つからない場合はどうなりますか？ =

そのような場合でも、サイト名・説明文・公開コンテンツ要約をもとにした「サイトについて」の一般的な案内に回答できます。無関係な内容を提示する代わりに、その旨を伝えます。

= AI の利用回数を制限できますか？ =

できます。設定画面には接続単位の利用回数上限（10 分あたり・1 時間あたり）と、サイト全体の AI 呼び出し日次上限があり、利用量やコストの管理に役立ちます。

= プラグインをアンインストールするとデータはどうなりますか？ =

選択できます。「Uninstall Data Policy」設定で、プラグイン削除時に設定・チャットログ・保存済みナレッジベースを保持するか削除するかを指定できます。

= プラグインを更新するとシステムプロンプトは上書きされますか？ =

上書きされません。システムプロンプトを変更していない場合はデフォルトに従い、更新のたびに改善された内容が自動で反映されます。カスタマイズしている場合はその内容を保持し、デフォルトが新しくなると設定画面に新しいデフォルトを表示して、切り替えるか今のプロンプトを使い続けるかを選べます。

= カスタムフィールドも検索できますか？ =

できます。ただし「検索対象のカスタムフィールド」に指定したキーだけが対象です（初期状態では何も検索しません）。カスタムフィールドには公開したくない情報が入っていることがあり、検索対象にした内容は回答を通じてどの訪問者にも見える可能性があるため、商品名や価格など公開してよい情報を持つフィールドだけを指定してください。

= チャットウィジェットを手動で配置するには？ =

`[ai_site_search_chatbot]` ショートコード、または固定ページ・投稿編集画面で AI Site Search Chatbot ブロックを追加してください。どちらも任意の `theme` 属性（`business` または `cute`）に対応し、ショートコードはさらに `title` と `greeting` 属性にも対応しています。

= 1.3.0 =
* 続けての質問で前の会話を引き継ぐようにした。ウィジェットが直近のメッセージを質問と一緒に送り、既存のルート判定の AI 呼び出しで、前の質問の続き（「何月のもの？」への返事など）かどうかを判断して単体で意味が通じる質問に書き直す。書き直した質問を検索・キャッシュ・保存済みナレッジ・ログに使う。管理画面のログには訪問者の実際の入力を「続けて入力された内容」として表示。AI の呼び出し回数は増えない
* 引き継ぐ直前のメッセージ数を設定する「会話履歴」を追加。初期値 4（直近 2 往復）、範囲 2〜10 で、サーバー側でも上限を強制
* 該当するページが見つからないときに AI が提案する再検索キーワードを、サイト内で実際に結果が出ることを確認した語だけに限定。候補は投稿タイトル（シリーズ名を含む）とタクソノミーのタームから作り、カスタム投稿タイプ名を添えて AI に渡す。候補は 1 時間キャッシュ。AI を使わない「見つかりませんでした」の回答にも数語を表示
* 「検索対象のカスタムフィールド」設定を追加。指定したキー（末尾 * で前方一致）の値を検索し、シリアライズや JSON の値も文章にして AI に渡す。初期状態は空で、設定画面にサイトで使われているキーを一覧表示
* ショートコードやプラグインの動的ブロックが出力する文章でもページが見つかるようにした。展開した文章は投稿ごとにキャッシュ（投稿の更新時または 12 時間で更新）し、1 回の検索で展開するのは最大 10 件、対象は新しい順に 100 件まで。新設の「ショートコードとブロックの出力」設定でオフにできる
* 検索結果の本文で、ショートコードより先に動的ブロックを展開するようにした
* デフォルトのシステムプロンプトがプラグインの更新に追従するようにした。カスタマイズしたときだけ保存し、過去のデフォルト（どの言語でも）がそのまま保存されているサイトは自動で現在のデフォルトに切り替える。カスタマイズしたプロンプトは変更しないが、デフォルトが新しくなると切り替えるかどうかを選べるお知らせを表示。プロンプトがデフォルトかカスタマイズ済みかの状態表示と「デフォルトに戻す」ボタンも追加
* 不具合修正: 部分一致の予備検索で、SQL に渡す値の順番が誤っていたため、一度も結果を返していなかった
* 検索語から日本語のかぎ括弧を取り除くようにした

= 1.2.0 =
* Saved Knowledge Base の編集画面で、参照元投稿 ID ごとにタイトルを表示（マウスオーバー）し、クリックで本文をポップアップ表示、別タブでの表示・編集ができるようにした。非公開・パスワード保護・削除済み・閲覧権限のない投稿は色分けして表示
* 承認済みナレッジで、公開されなくなった参照元投稿（非公開・ゴミ箱・削除・パスワード保護）を再利用の判定から除外するようにした。参照元がすべてなくなったナレッジは即座に使われなくなり、バックグラウンドでサイト内検索をやり直して回答と参照元を再生成したうえで下書きに戻す（回答が得られない場合も下書きに戻す）。通常の編集操作以外の変更も 1 日 1 回の巡回で検出
* サイト内検索の結果から古い情報を除外するようにした。日付と数字を除いたタイトルと本文冒頭がほぼ同じ新しい投稿がある場合（営業時間変更のお知らせの更新など）は、最新のものだけを AI に送り参照元に表示する。内容の異なる連載記事や定期報告は両方残す。あわせて公開日と今日の日付を AI に渡し、最新の情報を優先させる。いずれも追加の AI 呼び出しは発生しない
* 参照元投稿が現在の検索結果にある新しい投稿に置き換えられている承認済みナレッジは再利用せず、新たに回答を生成するようにした
* 日付や一時的・期限付きの情報（お知らせ、イベント、キャンペーン、締め切りなど）を含むナレッジ下書きは破棄せずに保存し、承認前に確認できるよう「日付を確認」の目印を付けるようにした。日付を含むだけの継続的な事実は通常どおり保存
